# Допущения и открытые вопросы

Решения, принятые при проектировании скелета. Всё, что помечено ❓, нужно подтвердить.

## Принято по ответам заказчика

- Точка опоры — Предрейс, данные синхронизируются; пользователи общие, регистрация через Предрейс.
- Фронтенд отдельный, разрабатывает другой человек → API-first, `docs/openapi.json`.
- Подпись выполняется в Предрейсе. XML-схему проектируем сами.
- ~1000 записей/сутки.
- `specialist_user_id` обязателен; у ЭПЛ «Водителя+» осмотры подписывает реальный медик/механик ПРЕДРЕЙС.
- Реквизиты в записи фиксируются на момент осмотра (`snapshot`).

## Допущения по неясным местам ТЗ

| № | Место ТЗ | Принято |
|---|---|---|
| 8 | Плашки подписи в PDF (стр. 5 п.16 vs стр. 19) | Плашек нет (раздел про формат выгрузки точнее) ❓ |

| 11 | Права редактирования техконтроля не указаны | Как у медосмотров |

| 14 | Подпись ЭПЛ-записей | В списке полей только метаданные сертификата. Без `signature_b64` документ создаётся без `.sig`, и в ZIP журнала такие записи пойдут без файла подписи ❓ |
| 15 | Состояние «ожидает подписи» | `reserved_journal_id` + статус журнала `awaiting_signature`; «Отклонить» снимает резерв |

| 23 | Уведомления | Outbox → `notify` Предрейса, рассылает Предрейс |
| — | Доступ клиента/диспетчера | Нужен `journals_access`, организация на ЭПЛ (не гибрид), только подписанные записи |

| — | Поля ЭПЛ, не имеющие колонок | `critical_flag`, `released`, `brakes_ok` и др. хранятся в `epl_details`; в PDF не выводятся ❓ (нужен ли `critical_flag` в логике?) |
| — | `approved` vs `released` (Т3) | Результат техконтроля берётся из `approved` ❓ |
| — | `exam_datetime` vs `recorded_at` | `performed_at` = `exam_datetime`; `recorded_at` — в `epl_details` |
| — | ЭПЛ-событие и реплики | Не создаёт и не меняет реплики; нет реплики → 409 и повтор. Снимок строится из события |

## Не реализовано (заглушки с описанием шагов в docstring)

- Сборка ZIP-контейнера и подпись журнала — `app/modules/ejournal/builder.py`.
- Распознавание сканов — `app/modules/ocr/service.py` (клиент Yandex Vision готов, формат сверить с документацией).
- Журнальный PDF с синей плашкой — шаблон `_base.html` (`stamp`) готов, вызова нет.
- XSD для XML записи и журнала — сейчас детерминированная схема-черновик (`signing/xml_builder.py`).
