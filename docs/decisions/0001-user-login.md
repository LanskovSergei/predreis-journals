# Решение 0001. Как пользователи входят в электронные журналы

**Статус:** ждёт решения (Ольга). Не технический выбор: от него зависит, сколько паролей у пользователей,
кто отвечает за доступы и что нужно доработать в ПРЕДРЕЙСе.

## Что известно

- Журналы — отдельный сервис на другом домене; фронтенд делает другой разработчик.
- По ТЗ пользователи общие: регистрируются в ПРЕДРЕЙСе, **доступ к журналам по умолчанию выключен**, включает суперадмин.
- Медики и механики подписывают записи **личным сертификатом в ПРЕДРЕЙСе**. Для подписи журналам нужен
  идентификатор пользователя именно в ПРЕДРЕЙСе (`signer_user_id`): по нему ПРЕДРЕЙС выбирает сертификат.
- Сегодня ПРЕДРЕЙС умеет только межсервисный контур (токен сервиса, справочники, очередь, подпись).
  Входа пользователей и списка пользователей в нём для журналов нет.

## Варианты

### A. Бесшовный переход из ПРЕДРЕЙСа (рекомендуется)

Пользователь входит в ПРЕДРЕЙС как обычно, нажимает «Электронные журналы» и попадает в журналы без второго пароля.

| Плюсы | Минусы |
|---|---|
| Один аккаунт и один набор паролей | Нужна доработка ПРЕДРЕЙСа (см. ниже) |
| Роли, блокировка и доступ действуют из одного места; отключение доступа вступает в силу в течение 15 минут | Журналы зависят от доступности ПРЕДРЕЙСа при входе |
| Идентификатор пользователя совпадает с ПРЕДРЕЙСом, подпись работает без сопоставлений | |
| Совпадает с тем, что уже написано в ТЗ | |

**Что нужно от ПРЕДРЕЙСа:** флаг «доступ к журналам» у пользователя и его включение суперадмином; выдача токена
для журналов (страница перехода, обмен кода на токен, обновление токена); публикация открытых ключей для проверки
токенов; кнопка в личном кабинете. Токен содержит: идентификатор пользователя, роль, признак доступа, организацию
(для клиентов), ФИО. Журналы к этому уже готовы: токены проверяются по открытым ключам, права разбираются по роли.

### B. Отдельный вход в журналы (свои логины)

| Плюсы | Минусы |
|---|---|
| Не зависит от входа в ПРЕДРЕЙС | Второй пароль у каждого пользователя, восстановление пароля, защита от подбора, двухфакторка |
| | Дубли пользователей и рассинхрон ролей и блокировок (уволили в ПРЕДРЕЙСе, а в журналах остался доступ) |
| | Нужно сопоставлять пользователей журналов с пользователями ПРЕДРЕЙСа, а API списка пользователей там нет, значит доработка ПРЕДРЕЙСа всё равно нужна |

Вариант кажется быстрее, но объём работы и поддержки в итоге больше.

## Рекомендация

**Вариант A.** Он совпадает с ТЗ, не создаёт второй базы паролей и снимает проблему с идентификаторами для подписи.
